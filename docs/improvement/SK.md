# 改进方案索引

---

## 一、改进机制

### 1.1 改进来源

| 来源 | 触发条件 | 处理流程 |
|------|---------|---------|
| 评审发现问题 | Code Review有驳回 | 整改 → 复审 |
| 生产问题 | 故障报告 | 分析根因 → 措施 → 验证 |
| 优化建议 | 风控分析师反馈 | 评估 → 实现 → 验证 |
| 标准化 | 做得好且可复用 | 提炼 → 归档为Skill |

### 1.2 改进闭环

```
发现问题 → 分析根因 → 制定措施 → 实施整改 → 验证效果 → 标准化沉淀
     ↑                                                    │
     └──────────────────── 复盘 ──────────────────────────┘
```

---

## 二、标准化落地

### 2.1 Skill归档标准

**归档条件**（满足任一）：
- 同一个问题出现≥3次
- 解决方案可复用
- 最佳实践被≥2个模块采用

### 2.2 Skill归档流程

```
1. 识别：Agent识别可标准化场景
2. 提炼：编写SK.md（模板见下方）
3. 评审：技术评审通过
4. 归档：放入skills目录
5. 推广：通知相关Agent使用
```

### 2.3 Skill模板

```markdown
# [技能名称]

## 问题场景
[什么情况下使用此技能]

## 解决方案
[具体实现步骤]

## 关键检查点
- [ ] 检查点1
- [ ] 检查点2

## 反例
[不应该的做法及后果]

## 相关文档
[关联文档链接]
```

## 三、整改管理

### 3.1 整改跟踪

| 字段 | 说明 |
|------|------|
| 问题编号 | 唯一标识 |
| 问题描述 | 详细描述 |
| 根因分析 | 5Why分析 |
| 整改措施 | 具体行动 |
| 责任人 | 指定人员 |
| 截止时间 | 计划日期 |
| 验证结果 | 通过/未通过 |

### 3.2 整改验收

- **短期措施**：发布后1周内验证
- **长期措施**：下一个灰度周期验证
- **标准化**：Skill归档后立即可用
