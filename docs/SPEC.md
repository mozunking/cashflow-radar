# CAD 产品规格说明书 (SPEC.md)

**版本**: 1.0 | **日期**: 2026-05-18 | **状态**: 草稿

---

## 1. 产品概述

**产品名称**: CAD (Capital Anomaly Detection) - 资金异常筛查算法模型模块

**一句话定义**: 为集团资金风控提供算法模型能力的平台，通过 API 供现有 Java 系统调用，实现从专家规则到"规则+算法"双引擎的升级。

**定位**: 现有专家规则引擎的**增量补充**，非替代。聚焦规则引擎无法覆盖的隐性异常、时序异动、资金链路异常。

---

## 2. 目标用户

| 角色 | 职责 | 使用频率 |
|------|------|---------|
| 账户/结算管理员 | 监督集团资金异常 | 每日 |
| 第三方软件公司 | 集成算法模型到客户系统 | 按需 |
| 审计人员 | 合规追溯36个月 | 按需 |

**三角色够用**: 管理员、分析师、审计员

---

## 3. 核心场景

### 3.1 算法模型开发与训练
数据科学家/分析师通过平台训练、评估、发布算法模型。

### 3.2 模型 API 调用
Java 系统通过 REST API 调用模型进行异常检测，获取解释结果。

### 3.3 模型迭代优化
基于反馈自动回流，2-3周迭代一次，用新数据验证历史模型。

## 6. 算法模型设计

### 6.1 模型类型

| 模型 | 算法 | 适用场景 |
|------|------|---------|
| IForest | 隔离森林 | 大额交易、非常规金额 |
| LOF | 局部离群因子 | 高频交易、密集划转 |
| Graph | 图网络分析 | 资金环路、多层嵌套 |

### 6.2 模型迭代

- **反馈闭环**: 自动回流机制
- **迭代周期**: 2-3周
- **历史验证**: 新模型需用历史数据重新训练验证

### 6.3 质量目标

- 误报率控制 (影响业务人员工作)
- 漏检可接受 (通过迭代优化)

---

## 7. API 设计

### 7.1 核心端点

| 端点 | 方法 | 说明 |
|------|------|------|
| /api/v1/detect | POST | 单笔交易检测 |
| /api/v1/batch-detect | POST | 批量检测 (T+1) |
| /api/v1/explain/{id} | GET | 获取异常解释 |
| /api/v1/feedback | POST | 提交反馈 |
| /api/v1/models | GET | 模型列表 |
| /api/v1/models/{name}/publish | POST | 发布模型 |

### 7.2 API 契约

- **稳定性**: API 签名尽量不变，保证 Java 调用方兼容
- **版本策略**: v1 长期维护
- **SLA**: 暂无明确要求，保证稳定性和兼容性

---

## 8. 数据管道

### 8.1 数据接入

- **模式**: 定时拉取 (从中间表)
- **数据源**: 数据中台关系型数据库
- **延迟预案**: 需处理数据延迟到达情况

### 8.2 数据安全

- 生产数据包含敏感信息
- 不能产生敏感数据泄露
- 国密算法用于传输/存储加密

---

## 9. 部署与运维

### 9.1 降级策略

| 状态 | 行为 |
|------|------|
| 模型正常 | 全部模型参与检测 |
| 部分模型失败 | 降级使用剩余模型 |
| 全部失败 | 服务不可用 (不回滚到专家规则) |

### 9.2 回滚机制

- 模型发布失败 → 回滚至上个版本
- 不支持回滚到专家规则引擎

### 9.3 无人工兜底

系统故障时不依赖人工干预处理。

---

## 10. 安全设计

### 10.1 国密算法

| 算法 | 用途 |
|------|------|
| SM2 | 签名/密钥交换 |
| SM3 | 消息摘要/完整性校验 |
| SM4 | 对称加密 |

### 10.2 认证与授权

- API 认证 (JWT/HMAC)
- 三角色权限: 管理员、分析师、审计员

### 10.3 日志审计

- 操作日志不可篡改
- 保留36个月
