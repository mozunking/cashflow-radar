## 一、检查标准体系

### 1.1 设计阶段检查

| 检查点 | 检查内容 | 通过标准 | 执行角色 |
|--------|---------|---------|---------|
| 需求评审 | US完整性 | 所有US有验收标准 | 产品 |

### 1.2 开发阶段检查

| 检查点 | 检查内容 | 通过标准 | 执行角色 |

| 契约测试 | 接口契约通过 | 100%通过 | CI |
| 安全扫描 | 无高危漏洞 | SonarQube Snyk | CI |

### 1.3 发布阶段检查

| 检查点 | 检查内容 | 通过标准 | 执行角色 |
|--------|---------|---------|---------|
| 回测验证 | F1≥0.75 | MLflow报告 | 数据科学家 |
| 性能验证 | P99响应达标 | 性能测试报告 | 测试组 |

## 二、多代理评审

### 2.1 评审角色

| 角色 | 职责 |
|------|------|
| 评审主持 | 协调评审会议、记录问题 |
| 代码作者 | 讲解实现、回答问题 |
| 评审员 | 提出问题、通过/驳回 |
| 记录员 | 记录评审意见 |

### 2.2 评审流程

```
1. 提前2天发送评审材料
2. 评审员预审代码
3. 评审会议（30分钟）
4. 评审结论：通过/驳回/有条件通过
5. 记录action items
6. 跟进整改
```

### 2.3 评审清单

| 类别 | 检查项 |
|------|--------|
| 功能 | 符合US验收标准 |
| 性能 | 响应时间达标 |
| 安全 | 无硬编码、无注入风险 |
| 可维护 | 代码清晰、有注释 |
| 测试 | 有UT、有契约测试 |

## 三、质量门禁

| 指标 | 阈值 | 超阈值处理 |
|------|------|-----------|
| UT覆盖率 | <80% | 禁止合并 |
| 代码重复率 | >5% | 禁止合并 |
| 安全漏洞 | 高危1个 | 禁止合并 |
| 性能不达标 | 任何1项 | 禁止发布 |
